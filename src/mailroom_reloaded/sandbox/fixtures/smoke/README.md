# Smoke set

The smallest pinned corpus that wires **mailroom-reloaded** end to end with
**zero network and no dataset access** (addendum v2 §2.4, §13.1; CD13).
`smoke` is the required CI profile in the main repo, so everything here is
`gen: scripted` and every document is a committed synthetic fixture.

## What is in it

`smoke_set.yaml` lists:

- `scenario_ids`: A1, A3, B1, D1, E1, F1 (status inquiry, supersession,
  amendment by title, red herring, lookalike wire change with its benign
  companion, hard negative).
- `stand_ins`: the pinned file that replaces each `{class, stratum}`
  dataset draw in those scenarios (today: the E1 companion's officer
  certificate).
- `documents`: GENERATED by `tools/export_smoke.py --write-set`, exactly the
  files the six scenarios use, with doc_id and sha256 from
  `attachments/manifest.csv`.

## Export

```
python3 tools/validate.py              # compiles dist/registry.yaml
python3 tools/export_smoke.py --out build/smoke
```

writes the directory mailroom-reloaded copies verbatim to
`sandbox/fixtures/smoke/` (PR 5a / M6):

```
manifest.json            content version, dataset revision, files {path: sha256}, total_bytes
smoke_set.yaml
registry.yaml            compiled registry (no adversary data, no labels)
scenarios/<name>.yaml    stand-ins applied: every document is {file: ...}
docs/<file>
templates/<name>.j2      only the templates these scenarios render
personas/personas.csv, personas/behavior/*.yaml
```

`--check` (run by `tools/ci.sh`) fails if the documents block is stale, a draw
has no stand-in, a document's bytes differ from the manifest, or the export
exceeds `budget_bytes` (2 MiB).
